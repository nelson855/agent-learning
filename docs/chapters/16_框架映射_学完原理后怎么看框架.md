# 第 16 章：学完原理后，如何看 Agent Framework

这一章不再实现新的核心机制。

目标是把已经手写过的概念映射到未来框架。

## 16.1 看任何框架都问这 10 个问题

1. `LlmClient / Model` 在哪？
2. Tool 怎么声明？
3. Tool 怎么执行？
4. Agent Loop 谁负责？
5. State 放哪里？
6. Memory 如何保存与检索？
7. Context 在哪里构造？
8. Checkpoint 怎么实现？
9. Guardrail 在哪一层？
10. Trace / Eval 怎么接？

只要回答出来，你就不会被框架 API 牵着走。

## 16.2 Spring AI / LangChain4j 类框架

更容易让 Java 开发者快速接入：

```text
Chat Model
Tool Calling
Memory
RAG
Advisor / Interceptor
Structured Output
```

学习时重点比较：

> 它把我们前面哪些代码封装了？

## 16.3 Graph / State 类框架

当你看到：

```text
Node
Edge
State
Checkpoint
```

不要觉得是一个全新世界。

你已经手写过：

```text
State_n
→ step
→ State_n+1
```

Graph 只是把状态迁移显式建模。

## 16.4 Coding Agent

看到 Codex、Claude Code 一类系统时，可以按 Harness 拆：

```text
Model
Tool / Shell
File System
Context
Planning
Progress
Compaction
Permission
Sandbox
Checkpoint
Evaluation
```

这样理解，比记住某个产品的命令更有迁移价值。

## 16.5 什么时候开始使用框架

当你已经能明确说出：

> “我现在不想自己维护 Tool Schema / Memory / Graph / Checkpoint，因此使用这个框架。”

这时框架是生产力。

如果只是：

> “大家都用，所以我也用。”

它反而会阻碍学习。
