# 技术基线与工程约定

## 固定版本

- Java：JDK 21
- Build：Maven
- Database：SQLite 本地文件
- JSON：Jackson
- Test：JUnit 5
- Stage Web：JDK HttpServer + HTML/CSS/原生 JavaScript

## Maven 编译配置

建议：

```xml
<properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>
```

## SQLite

建议依赖：

```xml
<dependency>
    <groupId>org.xerial</groupId>
    <artifactId>sqlite-jdbc</artifactId>
</dependency>
```

教学项目默认：

```text
./data/<lab-name>.db
```

Repository 直接 JDBC。

原因：

1. SQL 清楚可见。
2. 没有 ORM 隐藏状态持久化。
3. SQLite 易于清理和复现实验。
4. 后续 State / Memory / Checkpoint 都能直接观察表数据。

## LLM Client

推荐保持一个供应商无关接口：

```java
public interface LlmClient {
    LlmResponse chat(LlmRequest request);
}
```

配置：

```text
LLM_BASE_URL
LLM_API_KEY
LLM_MODEL
```

学习阶段优先 Java `HttpClient`，不要先依赖某家 SDK。

## FakeLlmClient

每一个涉及 LLM 的 Lab 都应考虑提供：

```text
FakeLlmClient
```

理由：

- 单元测试可重复
- 不需要网络
- 不消耗 Token
- 可以精确制造：
  - 错误 Tool
  - 缺失参数
  - 死循环
  - Replan
  - Evaluator fail

真实模型用于“观察智能行为”。

Fake 模型用于“证明程序逻辑”。

两者作用不同。

## SQLite 浏览建议

学习过程中经常直接打开数据库观察：

```text
task
message
memory
agent_run
checkpoint
trace
approval_request
```

不要只看控制台。

Agent 工程很多关键机制实际上是：

> 模型行为 + 程序状态 + 持久化数据

共同形成的。


## Maven 多模块仓库约定

整个学习仓库采用：

```text
一个 Git 仓库
+ 一个根 Maven 聚合工程
+ 多个独立 Lab Maven Module
+ 多个独立 Stage Maven Module
```

根 `pom.xml` 只负责聚合、统一 Java 版本、依赖版本和基础插件配置，不承载 Agent 业务代码。

每个 Lab / Stage 都有自己的 `pom.xml` 和可运行入口，可以在 IDE 中单独运行，也可以从根目录统一构建。Lab 通常使用 `Main`；Stage 2~4 可以额外使用 `WebMain`。

前半程不要创建 `agent-common`、`agent-core`、`agent-runtime` 之类公共模块。少量重复代码是有意保留的教学设计。

## Stage Web 技术基线

Stage 2~4 需要浏览器可视化时，默认只使用 JDK 内置 HTTP Server：

```java
import com.sun.net.httpserver.HttpServer;
```

前端使用：

```text
HTML + CSS + Vanilla JavaScript + fetch
```

不增加 Node/npm、Vue、React、Spring Boot。核心 Agent 层不能依赖 Web 层。
