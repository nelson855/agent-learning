# 仓库架构与构建说明

## 1. 为什么使用一个仓库

所有 Lab 和阶段综合项目放在同一个 Git 仓库，方便：

- 教材、Prompt、代码一起版本管理；
- AI 编程工具能够读取完整学习上下文；
- 统一 Maven/JDK 版本；
- 对比不同阶段的代码；
- 不需要维护几十个独立仓库。

但“一个仓库”不等于“一个巨大 Java 工程”。

## 3. Maven 的层次

根目录是 Maven 聚合父工程：

```text
agent-learning/pom.xml
```

`packaging` 使用：

```xml
<packaging>pom</packaging>
```

它只负责：

1. 声明所有 Lab / Stage module；
2. 统一 JDK 21；
3. 集中定义依赖版本；
4. 集中定义 Maven Compiler / Surefire 等基础插件版本。

根工程不要写 Agent 业务 Java 代码。

每个 Lab / Stage 自己仍然是一个普通 Maven Module，例如：

```text
labs/lab03-agent-loop-react/
├── pom.xml
├── README.md
└── src/
    ├── main/java/...
    └── test/java/...
```

## 4. 每个 Demo 怎么启动

### Lab：Main / CLI

绝大多数 Lab 都是控制台 Java 程序，不需要 Spring Boot，不需要 Web Server。

例如：

```java
public class Main {
    public static void main(String[] args) {
        // 构造本章需要的对象
        // 执行一个可观察的 Agent 场景
    }
}
```

在 IDE 中直接运行该 module 的 `Main.main()` 即可。

也可以命令行进入该 module：

```bash
cd labs/lab03-agent-loop-react
mvn test
mvn package
```

根目录可以统一验证所有已创建模块：

```bash
mvn test
```



### Stage：逐步增加可视化

Stage 的交互方式按学习复杂度递进：

```text
stage01-minimal-agent      → CLI
stage02-stateful-agent     → 简单聊天页 + State / Plan / Memory
stage03-long-running-agent → Context / Checkpoint / Resume / Evaluator 调试台
stage04-agent-harness      → Tool / Trace / Approval / Worker 综合控制台
```

Stage 2~4 默认增加 `WebMain`，使用 JDK `HttpServer` 启动本地页面。前端只用 HTML/CSS/原生 JavaScript。

典型 Stage 目录：

```text
stages/stage03-long-running-agent/
├── pom.xml
├── README.md
└── src/
    ├── main/java/...
    ├── main/resources/web/
    │   ├── index.html
    │   ├── app.js
    │   └── styles.css
    └── test/java/...
```

Web 层只是 Adapter。Agent 核心逻辑仍必须可以在不启动浏览器的情况下被测试。

## 5. 为什么每个 Lab 是独立 Module

因为每一章的第一目标是“看清概念”，不是最大化代码复用。

允许：

```text
lab02 有一份 LlmClient
lab03 再有一份类似 LlmClient
```

前半程不要急着抽：

```text
agent-common
agent-core
agent-runtime
agent-spi
```

否则学习一个 `AgentLoop` 需要跨多个公共模块跳转，反而难以理解。

## 6. Lab 与 Stage 的关系

Lab 是单概念实验：

```text
lab03-agent-loop-react
只研究 Agent Loop / ReAct
```

Stage 是阶段整合：

```text
stage01-minimal-agent
整合 Structured Output + Tool Calling + Agent Loop + ReAct
```

Stage 不直接依赖 Lab module，也不把 Lab 当作 Maven dependency。

正确方式是：

> 参考前面实验中已经理解的实现，重新在 Stage 中组合。

这样可以看到一个机制从“孤立实验”变成“系统组件”的过程。

## 7. SQLite 文件位置

每个 Lab / Stage 可以维护自己的本地数据库：

```text
<module>/data/<module-name>.db
```

例如：

```text
labs/lab06-state-memory/data/lab06-state-memory.db
```

SQLite 数据文件默认不提交 Git。

Schema 由程序启动时自动初始化，保持 SQL 简单可读。

## 8. AI 编程工具如何使用本仓库

无论使用哪一种 AI 编程工具，每次实现前都要求它读取：

```text
AGENTS.md
当前章节 docs/chapters/...
当前任务 docs/prompts/...
```

如果是 Stage，再读取：

```text
docs/stages/StageX_*.md
```

不要维护多套工具专属规则文件。仓库级统一约束是 `AGENTS.md` 与 `CLAUDE.md` 双镜像（内容一致，修改须同步）。

## 9. 第一次初始化

对一个空目录，先把 V3 教材包内容放入根目录，然后让 AI 编程工具执行：

```text
docs/prompts/00_repository_bootstrap.md
```

这个 Prompt 只负责创建 Maven 仓库骨架，不实现任何 Agent 概念。

完成以后应满足：

```text
mvn test
```

在根目录能够通过，然后才进入 Lab 01。
